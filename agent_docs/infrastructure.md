# Infrastructure

How WeatherGenerator is built, run, and developed.

## Package management: uv

The Python environment is managed with uv (https://docs.astral.sh/uv/).

- Python 3.12, pinned in `.python-version`.
- `pyproject.toml` — declared dependencies; the source of truth for what the project needs.
- `uv.lock` — locked exact versions; regenerated by uv, never edit by hand.

Commands:

```bash
uv sync                 # create/update the env from pyproject.toml + uv.lock
uv run <command>        # run a command inside the env
uv add <package>        # add a dependency (updates pyproject.toml and uv.lock)
```

Never `pip install` into the env — it bypasses the lock and drifts contributors apart.

## Where we run

- Most jobs (training, evaluation, inference, profiling) run on HPC clusters, submitted to the scheduler rather than run on a workstation.
- Development happens on the HPC (interactive sessions) or locally. Local is for editing, small tests, and tooling; anything needing real compute goes to the HPC.
